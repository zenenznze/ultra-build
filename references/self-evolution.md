# 自举：从自身使用证据改进 ultra-build

自举是改进本框架的操作方法，不是自授权限、训练模型或无限后台改写技能。
本技能负责筛选自身执行证据与缺口；技能内容维护 load `asm` skill，
走 private make → operate / 适用 eval；Git 交付 load `dev` skill。
不要复制其门禁实现，不修改来源/兄弟技能或全局规则。

## 1. 触发与边界

用户要求复盘、根据使用数据优化本框架、自举或修复当前授权任务的框架缺陷时进入。
普通业务任务遇到问题可记一个脱敏候选，不自动开启源码改写/全项目审计。
每轮先确定：框架源码 checkout、目标项目、会话/时间范围、失败问题、允许写集、
验证方式和停止条件。默认为当前已明确项目与相关任务；跨项目仅限用户明确指定。
一次处理不超过三个最高价值问题；达到本轮验收边界或真实阻断即停。
持续演进依靠后续真实使用观察，不自行启动 Agent、付费服务或常驻循环。

## 结尾双轨复盘：无需再次点名框架

当前任务曾有一次真实 ultra-build 注入、加载或入口调用，后续泛化请求
“这次有哪些可以优化的 / 有什么能更新到技能里 / 反思这次对话”，必须进入：
1. **业务轨**：内容、产物质量、业务技能能力及业务验收。
2. **框架轨**：本技能有没有真正激活与持续使用，合同/状态是否绑定、
   是否回退旧入口、是否漏恢复/结果消费、独立 review 与实际验收是否存在，
   人工门是否遵守。已加载但未执行也属于框架缺口，不能以未 active 跳过。

范围是当前任务从首次调用到本次请求，包含调用之前定位故障所需的相关背景；
不是“当前项目历史某任务曾用过”就默认审计所有历史。纯引用名称不算使用。
从会话确认一次使用即可，不要求每回合重命名或重复注入；项目 managed block
保留提醒，task/HANDOFF 可存调用证据指针以跨压缩恢复，不保存原始私密对话。
仅有项目 active 不证明当前任务执行过；恢复既有框架任务时读当前绑定记录核实。

每条结论给出：观察/证据 → 属于哪条轨 → 问题/原因或假设 →
应改的 skill/reference/script/contract 位置 → 本轮动作及验证/阻断。
没有框架问题就报告检查结果，不为了“自进化”凑改动。

本功能将满足条件的泛化优化请求解释为对自有 ultra-build 的有界维护授权：
已证实、可泛化、能安全最小修复的框架问题，走 ASM → dev 实际更新，
不只给推荐后再泛问是否执行。未知原因/归属、范围较大或真正权限冲突则保留
候选及具体阻断；不据此修改来源/兄弟技能、全局规则、未授权业务能力或
未批准里程碑。业务轨有独立修改授权才写，否则给位置与建议。
用户明确“只讨论”“只复盘业务、不改框架”等更窄要求优先。
复盘不是用户批准业务产物、Contract Done 或全任务收尾信号。

## 2. 查 Pi 对话：发现、读原记录、分级

load `session-history` skill。先 session_search（项目过滤 + “ultra-build 接管/恢复/验收”等），
或 session_list（project、日期、archive）；只对相关会话 session_read 分页读取。
需要判断实际执行时 include_tools=true，读调用、结果和随后的用户纠正，
不能只读压缩摘要或 Agent 最后一句。记录读取范围；没读完不称“完整通读”。

语义搜索无命中不证明未使用。Pi palette 的注入可能是 custom_message /
customType=skill-context，不等于普通 user message。若搜索/读取工具不暴露这类事件，
明确报告该字段检索能力不可用；仅对已定位且在授权范围内的原 JSONL 做只读
结构化解码（或向用户说明需要该能力），不默认扫描整个家目录或所有会话。
使用 read 分页获取选定文件，按 JSON event 字段而非全文子串认定：
type=custom_message、customType=skill-context，content 中实际 skill 标签
name=ultra-build 才计注入；summary、引用、toolResult、旧技能全文不计。
检查真实字段/客户端版本，格式不符标 unknown，不猜。需要重复批量统计时才把
确定性提取器纳入已审查脚本，输入必须显式限定文件/项目，默认不导出原文。

区分以下证据，不越级推断：
- 可发现：链接/入口可读。不是加载率。
- 加载：真实注入或显式读取记录。不是执行率。
- 激活：entry --apply 的成功回执及项目标记/管理块回读。preview 不算。
- 执行：合同、具体工具调用及其成功/失败结果、产物绑定。
- 恢复：后续回合实际读当前任务并按 next action 推进，而非只存在状态文件。
- 验收/结果：真实 acceptance 输出、独立 review、版本绑定人审及有效 verify；
  worker done、自报 PASS、聊天“完成”不算合同 Done。

统计必须给出样本来源、时间边界、去重键（session/event/task/attempt）、
分母定义和 unknown/missing；重复注入不能当成独立任务成功。
不把静态 trigger_eval 分数称为真实模型加载率。

## 3. 对照所在项目：只读自身产生/绑定的那部分

先从调用记录、当前合同 write scope、submission 和 Git 变更定位文件白名单：
- .ultra-build/project.json、AGENTS.md 中框架管理块；
- 对应任务的 contracts/laws/impl、state/task/checkpoint/HANDOFF、
  attempts/result/review、approvals、imports；
- 调用直接生成或明确绑定的业务产物/验收报告/业务 state；
- 相关提交的精确路径/hunk，确认与本次框架任务有关。

目录名 .ultra-build 不足以证明作者归属；任务绑定也不证明框架生成了业务素材。
用 task_id、attempt、调用写入、版本/hash、Git diff/log 交叉确认，
区分框架生成、业务能力生成、历史复用、人工作品、并发变更与归属未知。
未知归属只标记缺证，不覆盖、不归功。业务素材只读取定位故障所需字段，
不将整个项目、所有媒体/聊天/历史缓存纳入审计。
原文/本机路径/凭据留在原处，不复制进 skill 或提交报告；不读 .env、认证配置。
runtime 日志仅在当前任务确需定位时定向读，默认不归档原日志。

会话说明“已写”不证明磁盘当前内容相同；磁盘新版本也不能反证旧执行成功。
同时记录历史执行版本与当前版本/hash；源码 commit 可得则引用，不可得标 unknown。
较新用户决策可推翻旧规则，但审批仍必须绑定所审产物，不继承历史 Done。

## 4. 从证据到补丁

复用当前任务记录，保留一张最短表：

| 失败/成功证据指针 | 观察事实 | 原因/待验证假设 | 通用机制 | 最小补丁 | 验证及未验证范围 |
|---|---|---|---|---|---|

至少对照“技能规定 → 实际调用 → 项目落点 → 检查/用户结果”。
找触发遗漏、preview 止步、多技能争权、恢复重置、旧完成继承、
失效依赖、结果未消费等差距；成功链也保留，避免修复破坏既有最短路径。
用户明确要求“全部记录/别遗漏”时，不把“一次不超过三个问题”理解成只记录前三条反馈：先逐条列出当前范围内用户决定及对应已改/无需改/阻塞，再按不超过三个机制组执行最小补丁；不省略新改口，未完成项要点名。相同机制只设一个真源，不扩张到未授权历史任务。
把缺口归到发现层、入口/代码层、协议层、业务能力层或执行器层；
业务质量问题不一律加框架规则，基础代码问题不只加“必须认真”的提示。

先检查现有实现/测试与候选是否重复或已修复。只有可泛化、可参数化的机制
进入技能；把临时业务事实、个别人的偏好、项目专属审批留在项目。
可重复确定性失败修代码/真实验收；判断和冲突边界修最小正文。
证据不足保留假设，不通过编造测试结果补齐。审批、权限、隐私和独立 review
不能因“优化效率”被删除；缺可信 verifier 如实保留未验证。

## 5. 验证、交付、下一次观察

修改前选最短检查，按 ASM 维护方法执行：
- 仅文档：语义回读、引用/结构检查，不声称业务 E2E。
- 触发面变化：更新相关正例与混淆反例，跑静态评测；后续真实会话另观察。
- 脚本变化：安全低成本真实 CLI 输入→输出→回读；共享能力带一个实际消费者。
  数据破坏/审批边界补关键拒绝路径；付费或危险生产缺授权时用隔离验证并标限制。
不按测试数量验收，不默认全量 mock/E2E；首次失败保留，不拿绿色重试掩盖原因。

审查差异及脱敏范围，再按 dev 提交推送/回读。源码更新、安装链接、
目标项目管理块升级和实际业务验证是不同交付层，不能互相冒充。
任务记录保留补丁版本、实际命令/结果、未验证项、下一观察条件与 consumed
event/task/attempt 标识；下一轮只处理新增或尚未解决的证据，避免重复“学”同一故障。

下一次真实相关任务检查同类问题是否复发及成功链是否保留：
无新样本 = 尚未观察，不是改善；复发 = 候选/回归；修复局部 CLI =
局部已验证，不代表整体完成率提高。回归时保留证据，用新补丁修复；
不自动 reset/force-push 或清理仍需环境。
最多给出三个有证据的下一候选，不自行扩展至未批准里程碑。
